title: "★ Workflow — Parking Study (19 steps)"
---
**Trigger:** variance/reduction request, shared-use agreement, "do we have enough parking," due diligence.
**Inputs:** site plan w/ stall inventory, land-use program (sizes, units), jurisdiction code section, access locations.

1. Understand project type & land uses (program table with SF/units/seats — the demand basis).
2. Pull local parking code → a parking-code note (ratios, shared provision, reduction path).
3. ITE Parking Generation rates if applicable (LU code, edition, setting; avg vs 85th — ask what agency accepts).
4. ULI Shared Parking applicability (≥2 uses with offset peaks?) → plan the model.
5. Define study area (site-only vs incl. on-street/nearby public — agency guideline governs).
6. Inventory supply: total by type (standard/compact/ADA/EV/reserved/loading), on/off-street map.
7. Collect occupancy: hourly circuits covering expected peak periods; **≥1 typical weekday + weekend day if retail/mixed; avoid holidays/events; log weather** → the field-data sheet.
8. Observed peak demand: accumulation curve; peak hour, peak occupancy %.
9. ITE estimate: rate × units; show work.
10. ULI shared model: [[ULI Shared Parking Calculation]].
11. Apply/justify every adjustment (hourly, monthly, weekday/weekend, modal, non-captive, captive) — each with a sourced basis line.
12. Demand vs supply table (all four demand columns side by side).
13. Demand vs code requirement; compute surplus/deficit vs code.
14. Shared-parking opportunities (agreements, time-restricted stalls, valet, wayfinding).
15. Operational issues observed (queuing at gates/drive-thru spillback, circulation conflicts, illegal parking) — photos.
16. Exhibits: inventory map, occupancy heat map by hour, accumulation curve, ULI table.
17. Findings & recommendations (numbers first, adjectives never — "peak demand 412 vs supply 460 (90%)" ).
18. **QA/QC:** counts foot to raw sheets · ratios traced to code section text · ITE LU codes right edition · every ULI factor sourced · exhibit numbers = table numbers = text numbers · [[QAQC System]] Layer 1.
19. Final memo/report → a close-out parking-study note archives assumptions + lessons.

**Time it actually takes:** small site ≈ field day + 2–3 analysis/writing days (calibrate your own).
**Practice question:** observed peak is 55% of code requirement — list three explanations you must rule out before recommending a reduction.
**QA/QC reminder:** the four-way demand comparison table appears, or the study isn't done.
