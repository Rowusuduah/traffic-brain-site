# Workflow — Redline Response
1. Scan ALL markups before touching anything (Bluebeam: flatten copy for reading; keep original) — group by theme; conflicting comments → ask before editing.
2. Log every markup in [[T - Redline Response]] (sheet/location/says/action) — memory is not a tracking system.
3. Make changes theme-by-theme, not page-by-page (consistency: a fixed callout on Sh.4 exists on Sh.9 too — search the set).
4. Anything unclear = question WITH proposed interpretation ([[Questions for Senior Engineers]] format), never a silent guess.
5. Self-check pass: re-plot changed sheets; run [[SPM Plan Review Checklist]] deltas; verify no reference/level damage.
6. Return package: marked-up-vs-revised or response log; state anything intentionally NOT changed and why.
**Bluebeam habits:** comment list export = your log starter · status flags (accepted/completed) · compare-documents for version diffs.
**QA/QC reminder:** zero silent skips — every markup has a written fate.
